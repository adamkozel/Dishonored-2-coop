## Native consumption call chain

[Raw decompilation and negative xref queries](../../work/ghidra-potion-consumption-v65.json) are retained. Defined-string Ghidra xref queries returned no references to several strings, but the existing [PE RIP-reference scan](../../work/find-rip-refs.cjs) found `ConsumeHealthPotion` at RVA4f6695 and `ConsumeManaPotion` at RVA4f66f4, both in function1404f65b0. Decompiling that function confirms registration of1404f5fb0 and1404f5ff0 respectively. Missing defined-string xrefs did not mean the code was absent.

- Health callback1404f5fb0 resolves the health component and calls1407194a0. Eligibility is checked by140718ce0. The consume routine spends one inventory entry through1406147f0, applies difficulty/attribute-adjusted health through140719fe0, sends event0x15c, and increments statistic0x16. The **drinking sound event** from health declaration+d8 is queued as message0xa9 only when native logic is not8.
- Mana callback1404f5ff0 resolves the mana component and calls140745b20. Eligibility is checked by1407459f0. Consumption has attribute-dependent random branches, inventory spending, mana gain and statistic0x17; the **drinking sound event** at declaration+80 is likewise suppressed in logic8. These fields and branches require live correlation before use as a gameplay protocol.
- 1406147f0 addresses a56-byte inventory entry by index, decrements through14063c800, notifies1406170b0, sends a depletion message when reaching zero, and queues inventory message0x9c. It is different from the fixture's absolute-quantity grant/rollback function140618de0.

The initially generic interpretation of message0xa9 as an effect was narrowed by [reflection decompilation](../../work/ghidra-potion-reflection-v65.json):14165daf0 maps health declaration+d8 and14165e340 maps mana declaration+80 to `arkDeclSoundEvent m_consumeSoundEvent`. [Exact Void exports](../../outputs/d2-coop-lab/research/asset-exports/native-elixir-components-v65/manifest.json) name the native health/mana drinking sound assets. Separately, the string `m_healthPotionEffect` belongs to `arkDeclDifficultyManager::factorMultiplier_t` in141802090. Its name does not establish a visual effect.

It requires the active finite grant, observed exact item ownership, normal gameplay, original world, engine thread, exact callback bytes, and living health below maximum; it calls the native health-consume routine once. There is no direct health setter, mana setter or hand/scene override. The existing native wheel test established this routine's callback chain; calling it directly is explicitly recorded as a native callback test, not keyboard input.
