# Grenade network presentation development v56

This is an active, incomplete candidate. Successful source/prop checks do not establish grenade gameplay replication or a complete moveset.

[The bank builder](../../work/natural-moveset/build_grenade_bank_v56.py) appends nine pure-pose phases to D2MOVE42: held idle, equip, unequip, cooking entry, cooking loop, high throw, high empty recovery, low throw and low empty recovery. All 251 earlier v46 clip payloads remain byte-identical. [The manifest](../../work/natural-moveset/grenade-bank-manifest-v56.json) pins both native skeleton layouts, authored sources and output hashes. It also generates wrist-relative attachment tracks. Player world position, first-person animation and actual gameplay events are untouched.

Semantic protocol 37 appends four bounded fields: grenade presence, native phase, elapsed milliseconds and exact duration. [GrenadePresentation](../../outputs/d2-coop-lab/src/grenade_presentation.h) applies the same delayed source clock as body movement. Standing native regular-grenade actions alone are recognized. Invalid durations, orphan phases, concurrent gun/power/carry ownership, old sessions/worlds/tokens, duplicate or reversed events and stale data are rejected. The cooking-loop restart creates a fresh presentation event. Crouched/airborne/slide/reload/other grenade types remain unsupported by this candidate.

The held cosmetic prop hides at the authored native high-release reference (293 ms of 400) or low-release reference (302 ms of 400), and remains absent during empty recovery. It has no projectile or damage components. A real throw is created once by the local game's ordinary input path. Flight, detonation, world damage and corresponding remote effects remain to be synchronized. Native first-person fire events are never replayed by the authored body clips.

## Remaining grenade work

### Follow re-arm clock regression

v56d/e preserve detailed rejection categories. The [v56e readiness failure](../../work/natural-moveset/grenade-network-corvo-high-v56e/ready-failure.json) records action-clock rejection 11 at a mapped age of -87.57221 ms: the message appeared more than 80 ms ahead of the receiver. `beginProbeFollow` and the smoothing command reset the shared source clock and fed the cached remote root back into `bufferPresentation` as if it had just arrived. That adds the cached packet's age to the new offset. The established 1 ms/second drift correction cannot promptly undo this error.

Candidate [v56f](../../work/movement-integration/candidate-grenade-stream-v56f/identity.json) clears only the render buffer when re-arming follow or changing smoothing. The peer clock remains established; actual newly received packets refill the buffer. Session/world replacement and genuine long-outage clock resets remain handled by `SourcePoseTimeline`. [The regression check](../../work/movement-integration/grenade-stream-clock-v56f.log) demonstrates the cached-rebase hazard and verifies a fresh root/action remains inside the original freshness limits after clearing the render buffer. Protocol, actual-bank and loader checks also pass. The [v56f native attempt](../../work/natural-moveset/grenade-network-corvo-high-v56f/result.json) still failed readiness, without the future-clock rejection. This fix alone did not establish a working stream.

### Source read latency

[v56g diagnostics](../../work/natural-moveset/grenade-network-corvo-high-v56g/ready-failure.json) measured source reads up to 78.9584 ms on the observer and 81.061 ms on the source, with no failed source reads or invalid outbound packets. The observer retired at a service-time state age of 281 ms; the source later retired at 266 ms. Actual stop-time ages were 359 and 375 ms because more work occurred inside the same engine callback. Thus the remaining failure included real sampling/service delays; it was not unsigned subtraction underflow.

Candidate [v56h](../../work/movement-integration/candidate-grenade-stream-v56h/identity.json) batches printable identity-string reads into at most 32 bytes per memory call. It does not cache game memory or relax the 192-byte limit, printable-character checks, native identity checks or re-read guards. If a chunk crosses an unreadable boundary, it falls back to the original byte-wise behavior. The complete [native identity suite](../../work/movement-integration/grenade-stream-identity-v56h.log) passes, including new full-length, terminator, unreadable-boundary, invalid-character and pointer-overflow cases.

The [v56h live test](../../work/natural-moveset/grenade-network-corvo-high-v56h/result.json) reached automatic remote held-grenade presentation and received all native cooking/release/recovery phases. The body nevertheless failed the action-phase assertion: movement weight became zero as soon as ThrowWeapon62 joined Running0 because the independent motion reader did not recognize that exact combination. [Actual-game temporal evidence](../../work/natural-moveset/grenade-network-corvo-high-v56h/native-sheet.jpg) was inspected against [the source recording](../../work/natural-moveset/grenade-network-corvo-high-v56h/source-sheet.jpg): native source cooks and throws, while the remote remains in its default pose. Both isolated checkpoints and original health were restored by the completed harness.

## Interruption cleanup and menu recovery experiments

Both inventories/checkpoints return to their original state and fourteen protected hashes match. Both source and receiver temporal sheets were inspected and indexed for each case. Result text saying “at release” in these older harness checks means retirement by the explicit interruption, not an observed normal throw release.

These three runs explicitly disable automatic menu recovery. In both pause runs the remote body becomes invisible and remains absent after the menu closes; they establish cleanup, not resumed playable movement. The receiver-stop run leaves a native idle body visible.
