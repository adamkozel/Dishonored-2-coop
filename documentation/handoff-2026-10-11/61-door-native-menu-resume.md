# Ordinary doors survive native pause and resume

This follows [same-map checkpoint renewal](60-door-session-checkpoint-renewal.md). Candidate769 fixes a native pause-menu failure in the persistent ordinary-door session. The original Steam executable/assets/API DLL, local first-person controls, existing animation banks and isolated saves are preserved. This does not complete shared world authority or the movement phase.

## Reproduced problem

[Baseline768](../../work/natural-moveset/native-door-menu-baseline-v768/result.json), on preserved candidate763, armed six eligible Dunwall doors and opened Corvo's native pause menu. Both peers continued exchanging fresh poses on the same map and epochs, but every channel failed `world_input_or_connection_scope_changed`; both catalogs ended `all_channels_retired`. Returning to gameplay did not recover them. The failed receipt, both 20-second native recordings, contact sheets and native observations are retained. Cleanup restored complete inventories, player/counterpart health56/40 and all14 protected save/settings files.

## Implementation and native boundary

[door_session_scope.h](../../outputs/d2-coop-lab/src/door_session_scope.h) now distinguishes a retained same-world menu context from permission to mutate a door. It requires the original session pair, map, both world epochs, valid opposing roles, live pose flags and recognized native states. Candidate769 retained Gameplay1, pause2, ReadNote4 and state13, including pending transitions. **Correction from the subsequent death test:** state13 is native GameOver, not the weapon wheel; the old label and assertion that all death states were excluded were wrong. Candidate779 removes13 from ordinary-menu retention, and782 handles pending/committed death through the separate checkpoint barrier. Candidate769 runtime coverage in this chapter remains pause2 only. State8 was observed during the native weapon wheel in older66 evidence, but wheel retention is still not runtime accepted. See [continuous recovery](62-continuous-checkpoint-death-recovery.md).

[door_sync.h](../../outputs/d2-coop-lab/src/door_sync.h) suspends the entire persistent door catalog when either peer enters that context. No native queue call or door-packet apply occurs during suspension. Original component bindings and channel arms remain, and native identity/eligibility is reread when ordinary gameplay resumes. A missing/stale pose for one second, disconnected/changed session, uncoordinated world change or unsupported phase still retires intent. Coordinated checkpoint recovery retains its separate new-world path.

On resume, the measured suspended duration is added to existing desired-state and in-flight deadlines; unset deadlines remain unset and addition is overflow-safe. Old Hello freshness is discarded. Each channel requires a fresh Hello on its existing arm before ordinary servicing. The host republishes its current desired state, and a client with an outstanding request can send its retained intent in a new envelope. A newer local door action observed after resume supersedes that retained intent. Old menu packets are not replayed as native actions. The outstanding-request retry branch is implemented but these tests do not deliberately force packet loss or an unacknowledged request across the boundary.

The queue is still the verified exact native `14074a400` entry. Native animations, active opening-side checks and the previous close/reopen direction correction remain intact. No door transforms, raw machine states or opening-side fields are copied across games. The change only affects explicitly armed persistent session mode; the older finite fixture mode is retained.

Diagnostics add the root `menu` object to `coop-status.json.door-sync.json`: `suspended`, `since`, `suspensions`, `resumes`, `pausedMs`, and `packetsIgnored`. Ignored/rejected boundary packets are not claimed to be zero; the resumption handshake and host-state retransmission handle them. No unsolicited player-facing UI is added.

## Remaining work

Repeated shared loads and shared death/retry inside one continuously armed session remain to be tested. Runtime ReadNote/wheel, deliberate packet-loss recovery, long menu holds, real-account disconnect/reconnect, dynamic door eligibility, locks/groups/scripted doors and other maps are not accepted by this batch. The subsystem suspends door replication; it does not implement a whole-world cooperative pause.

Shared loot/food, inventory/progression, general AI/combat authority, the remaining native movement contexts, campaign/save boundaries, player-facing native session UI and separate-account Steam play still require implementation and validation. Continue toward the full co-op objective; do not count the number of videos as completion. Existing actor/world addresses and decompilation notes retain their previous confidence; this chapter records new mod-runtime evidence, not a new native decompilation claim.
