# Native Steam shared coin pickup

This continues [native coin lifecycle and reward research](63-native-coin-pickup-and-reward.md) using the existing pipeline. It adds a real network path for **one named ordinary Dunwall coin**, not a general shared inventory or completed co-op campaign. Original Steam assets, first-person controls and animation banks are unchanged. The native game supplies the source pickup action and both money notifications.

## Implementation

Files:

- [coin_protocol.h](../../outputs/d2-coop-lab/src/coin_protocol.h): packed480-byte protocol1 envelope and once-only award receipt.
- [coin_native_api.h](../../outputs/d2-coop-lab/src/coin_native_api.h): code/event guards, native player/wallet ownership, five-call recipient application.
- [coin_sync.h](../../outputs/d2-coop-lab/src/coin_sync.h): source reward observer, thread-safe observation queue, authored binding, Steam handshake, host commit, duplicates, menu retention and checkpoint lifecycle.
- [coin_protocol_tests.h](../../outputs/d2-coop-lab/src/coin_protocol_tests.h): malformed/foreign envelopes, role authority, stale epochs, exact deltas, simultaneous receipts and partial-application no-retry tests.
- [engine_bridge.cpp](../../outputs/d2-coop-lab/src/engine_bridge.cpp): command allowlist, observer installation, packet receive dispatch, engine service and periodic diagnostics.
- [checkpoint_sync.h](../../outputs/d2-coop-lab/src/checkpoint_sync.h): begin/complete/failure integration, independent of whether the door session is enabled.

The ordinary native `140841030(state,pickable,fromGrapple)` entry is observed. Its first16 bytes contain complete stack-save instructions with no relative branches or RIP-relative accesses; the exact32-byte prefix is verified before installing an absolute jump. The original16 instructions execute through an executable trampoline, then continue at entry+16. The original reward call always executes exactly once, including unsupported observations. A remote application calls the saved original directly, avoiding a network echo.

The source observation requires the bound actor/component/declaration/item incarnation, ordinary claimed coin flags, correct player/default-mode LootObject state47, owned inventory and an exact currency delta of one. It does not infer collection from a missing entity or unrelated wallet change. The native source code still owns its pickup motion, event and removal.

On the receiver, the engine service validates current world/thread, fresh paired gameplay, exact native API signatures and `pickedUp` descriptor. It waits for an idle grounded native player. If the receiver already has a local claim in progress, it waits for that native award rather than starting a second pickup. Application reserves a receipt before the first mutation, then calls native claim76e2b0, reward841030, pickedUp8848a0, result-variant cleanup882fc0 and finish76ec20. A failed/partial application is terminal for that incarnation; there is no blind retry or raw currency/picked-flag write.

Messages use existing native Steam `SendMessageToConnection` with `ReliableNoNagle`. Hello exchanges authored identity and local arm. Client Request reports an observed native award; host Commit authorizes one award per local world; Ack confirms the client's receipt. Both source/target sessions, epochs, arms, map, role, sequence and canonical identity strings are checked. One target has one host revision. Repeated packets, simultaneous native awards and retransmitted requests converge on that same receipt. Wallets receive the declared delta; the code does not overwrite one player's total with the other player's total.

Native pause2/ReadNote4 retain identity and pending intent, but recipient application requires both native gameplay contexts. Resume refreshes Hello and retransmits retained intent. The checkpoint barrier stops actions and retires the hook lease; coordinated completion requires both new epochs and restored roles/avatars before binding the restored coin with fresh arms and an empty per-world receipt. An uncoordinated world change, unsupported phase, disconnected session or stale peer stops the channel.

Developer-only commands are `coop_coin_sync on`, `off`, `duplicate` and `stale`. The last two replay an existing packet for refusal tests; they do not construct a new reward. This is not yet a native player-facing session menu. Periodic receipts are `coop-status.json.coin-sync.json` and `coop-status.json.coin-hook.json` inside each isolated instance directory.

## Confirmed thread finding and failed attempt

[Host take793](../../work/natural-moveset/shared-coin-host-v793/result.json) picked up the exact coin normally: source money0->1 and source actor removal, peer money0. Candidate792's engine-thread-only observer saw no source award, so it never sent a commit. Both sides were restored and that failed paired recording is retained.

Candidate794 publishes a copied immutable binding under an SRW lock. The native callback copies only the matching lease, performs its native reads/original call outside the lock, and places a bounded observation in an eight-entry queue. The engine service consumes matching arm/epoch observations; old-world observations are rejected. Network sends and diagnostic file writes stay out of the native callback.

Runtime795 establishes that this matters: host callback thread94880 differed from engine-service thread96248; hook counters reported one candidate and one call on another thread. The equivalent ordinary-source path also passes for Emily. This is runtime evidence for the tested pickup, not an assertion that every game callback uses that thread. The persistent Ghidra bookmark at `140841030`, category `CoopPickupResearch`, records this finding; the exact MCP export is [798](../../work/handoff-project-bookmarks-coin-v798.json).
